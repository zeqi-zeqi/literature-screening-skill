# Audit and checkpoint schema

All JSONL files contain one compact UTF-8 JSON object per line. IDs are positive integers assigned in source order.

## Prepared records

`records.jsonl` is generated by the helper:

```json
{"id":1,"sha256":"...","raw_text":"TY  - JOUR\r\n...\r\nER  - \r\n\r\n"}
```

`raw_text` is the exact UTF-8 record block excluding the file-level BOM. Do not edit it.

## Screening pass

Use `pass1.jsonl` and, when configured, `pass2.jsonl`:

```json
{
  "id": 1,
  "title": "Record title",
  "evidence": {
    "population_or_setting": "Short evidence or 'not reported'",
    "intervention_or_exposure": "Short evidence",
    "care_or_topic_context": "Short evidence",
    "study_type_and_outcomes": "Short evidence"
  },
  "label": "Include",
  "reason": "Brief criterion-linked reason.",
  "uncertain": false
}
```

Every configured evidence field must appear. Additional evidence fields are allowed only when the configuration requests them.

## Final decision

`final.jsonl` must contain every source ID exactly once:

```json
{
  "id": 1,
  "final_label": "Include",
  "adjudication_reason": "Brief final reason.",
  "adjudicated": true
}
```

Set `adjudicated` to `false` when matching, certain passes were accepted without rereading under the configured triggers.

## Progress checkpoint

Write `state/progress.json` atomically by creating a temporary file and renaming it:

```json
{
  "source_sha256": "...",
  "record_count": 702,
  "mode": "double_independent",
  "pass1_completed_through_id": 100,
  "pass2_completed_through_id": 0,
  "adjudication_completed": false,
  "next_action": "pass1:101-150",
  "updated_at": "2026-01-01T00:00:00.000Z"
}
```

Never infer completion only from the largest ID. Validate the complete expected ID set for every finished stage.
